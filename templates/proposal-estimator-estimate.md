# Proposal Estimator Template

Each estimate response should be structured as follows:

```md
# <Project Name>

## Assumptions

- <assumption>

## Open Questions

- <question that would materially change the estimate if answered differently>

---

### <Area Name> — <X>h

- <sub-task>
- <sub-task>

### <Area Name> — <X>h

- <sub-task>

---

**Base Total: X hours**
**Contingency (<confidence level> — <percentage>%): +Y hours**

**Best Case: X hours**
**Expected Case: X hours**
**Worst Case: X hours**
```

Keep the work breakdown concise. Area names and sub-tasks should be short and developer-readable, matching the level of detail in a real work breakdown — not prose descriptions.

Omit Assumptions and Open Questions sections only when there are none remaining after the interview.
